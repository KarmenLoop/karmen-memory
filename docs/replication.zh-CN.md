# 离线副本与宿主配置 — v0.3.0

[English](replication.en.md) · [中文](replication.zh-CN.md)

本版本基于现有记忆服务扩展，保留已确认事实、不可变修订、提取、检索、CLI 凭据和 v0.2.0 数据库，无需导出再导入。升级前停止旧进程、私下备份整个数据目录，再以同一 `KARMEN_MEMORY_HOME` 启动 v0.3.0。

## 安装与宿主连接

下载 v0.3.0 运行包，使用 Node 22.16+，在解压目录运行 `npm ci`、`npm start`。源码包还需 `npm run build`。保持服务运行，在本机控制台的工具授权页创建限定项目的 agent 凭据。将包含 `url`、`token` 的私有 JSON profile 放在 Git 之外并设为 0600；远端 profile 还可填写 `ca`，指向已核对的证书文件。

```sh
node bin/install-host.mjs --host codex --workspace /path/to/project --profile /private/codex-memory.json
node bin/install-host.mjs --host cursor --workspace /path/to/project --profile /private/cursor-memory.json
```

各宿主使用独立凭据。安装器保留其他条目、验证 TOML/JSON，并拒绝覆盖同名服务器。重载宿主，仅信任自己的项目，批准这个特定 MCP 服务，再实际调用 `memory_search`。原有 CLI/MCP 合同兼容，建议仍需人工审核；宿主仍需自己的登录与模型权限。

## 配对离线副本

1. 两台电脑分别安装并运行 Memory，使用不同私有目录、保留各自身份。
2. 在接收端开启局域网共享，下载公共证书，通过可信渠道核对 SHA-256 指纹，仅向预期局域网开放 HTTPS 端口。
3. 在新增的“离线副本”面板填写具体授权项目并生成一次性同步代码，有效期十分钟。它与原来的远端检索配对代码相互独立。
4. 在另一端副本面板填写接收端私有 IPv4 HTTPS 地址、已核对的 PEM 证书、代码与本机设备名，不要关闭证书验证或绕过浏览器 TLS 警告。
5. 在授权项目创建或批准“全设备”记录，点击“立即同步”。另一端应出现同一事实 ID、内容与来源，并保留本机修订历史。“仅本机”记录、待审核建议、凭据、API 配置与执行授权不进入同步流。

一个发起连接即可双向同步，服务运行期间自动重试。停止一端、在另一端修改记录，再使用原目录启动并同步，应能收到离线变更。正常退出仍按原服务规则关闭局域网监听；接收端重启后需明确重新开启局域网共享，其他副本才能重连。并发离线编辑保存在副本面板中，选择版本后再同步传播决定；存在未处理冲突时会阻止普通编辑。

记录传给其他存储后，项目与共享范围固定。需要撤回或迁移时，在面板明确删除后，再按期望范围新建。删除会移除当前事实与其修订正文，并传播删除标记，阻止并发旧编辑恢复内容。审计记录、无关候选、导出与备份单独保留，不承诺 SSD 物理抹除。

接收端“撤销”会立即拒绝副本凭据。发起端“停止”只关闭本机连接，还需在接收端撤销。恢复授权时重新生成代码配对。普通远端检索凭据不能调用同步 API。

## 维护与恢复

同步元数据与导入事实在同一 SQLite 事务中提交，原有一致性数据库备份会包含这些表。整个私有目录还包含 TLS 文件，应整体保留；不要把同一备份同时作为两个相同身份的在线存储运行。原 JSON 导出包含事实，不包含连接秘密或副本台账。

按原局域网流程更新到期证书或地址，核对新指纹并重新配对。证书错误、凭据撤销、网络故障或版本碰撞都会保留本机数据并报告错误，使用持久退避重试；没有响应不能当作同步成功。

## 验收边界

macOS 上使用真实 HTTP/HTTPS、两个独立存储、CLI/MCP 进程、离线冲突/删除/重启检查和真实 Codex 模型回合验收。Cursor MCP 管理器已发现工具，但模型回合受本机登录和账号额度限制。物理双机和 Windows/Linux 原生操作仍未验收。不提供托管云或调度器，保留原有关键词检索及本地句子提取行为。
